# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses
[semantic versioning](https://semver.org/).

## [Unreleased]

### Added
- Project plan, requirements, milestones, and V&V plan (`docs/`).
- Project scaffold (M0, tasks T0.1 and T0.2):
  - `src/` package layout with one subpackage per work package;
  - `psfwidget --version` command;
  - ruff, strict mypy, and pre-commit configuration;
  - GitHub Actions CI on Windows, macOS, and Linux with Python 3.12–3.14;
  - an 85% coverage gate.
- Requirements traceability:
  - `docs/traceability.csv`, generated by `tools/traceability.py`;
  - a `pytest.mark.req` marker that links tests to requirement IDs;
  - a `--req-report` option that writes requirement coverage per test run.
- Golden test data (M0, task T0.3):
  - `tests/data/manifest.json` with hashes, licences, and expected reader
    values for eleven files (two CZI, two LIF, five ND2, an OME-TIFF, and a
    TIFF); five are public and run in CI;
  - `tools/fetch_test_data.py` to download and verify them;
  - a `golden_file` pytest fixture.
- Licence audit (M0, task T0.5): `docs/LICENSE_AUDIT.md` and
  `tools/check_licenses.py`, which fails CI on a GPL/AGPL or unlicensed
  dependency.
- Synthetic bead fields (M0, task T0.4): `psfwidget.synthetic` renders
  Gaussian beads with known ground truth through a camera model (shot
  noise, read noise, gain, offset, bit-depth saturation), with doublets,
  hot pixels, tilt, curvature, and channel shifts.
- File import (M1):
  - `psfwidget.io.read_stack` and `list_series` for ND2, LIF, CZI, TIFF,
    and OME-TIFF, with series, timepoint, and tile selection;
  - acquisition metadata with the origin of every value (file, profile,
    or user), plausibility warnings, and a check that refuses analysis
    when a required value is missing or the image is not a 3D stack;
  - corrections for vendor metadata faults found in facility files
    (Leica sequential scans and negative z step, Zeiss dye-versus-laser
    wavelengths, Nikon band-edge emission and wrong channel excitation);
  - pixel data read one channel at a time, on request;
  - SHA-256 provenance.
- Instrument profiles (M1): TOML files that supply bead size, dye emission
  peaks, and optics per microscope; examples in `examples/profiles/`.
- `psfwidget info FILE` command: lists series and shows the resolved
  metadata, where each value came from, and whether the stack is ready
  for analysis.

- Bead measurement (M2):
  - `psfwidget.analysis.analyze_stack` and the `psfwidget analyze` command,
    writing per-bead, summary, and per-channel CSV files and a JSON record;
  - bead detection with hot-pixel removal; rejection of beads near the
    edge, overlapping, saturated (including saturation inferred from a
    clipping plateau), faint, poorly fitted, or outlying, each with a reason;
  - FWHM from 1D Gaussian fits along x, y, and z and from 2D fits in the XY,
    XZ, and YZ planes, with fit quality and uncertainty;
  - integrated intensity, peak, background, SBR, SNR, and ellipticity;
  - bead-size correction;
  - a measurement box that adapts when beads are much wider than theory,
    and is clipped at the image edge for short stacks;
  - summary statistics per channel.
- Theoretical PSF (THE-01, THE-03, THE-08): published formulas for
  widefield and confocal, and a numerical scalar model for any pinhole size,
  which the measured/theoretical ratios use. Resolution-enhanced modes are
  compared with their base modality.
- Spec limits (THE-06): `[spec]` table in instrument profiles, evaluated per
  channel; `--fail-on-spec` exit status.
- Undersampling warnings (MET-16).
- `tools/fitting_accuracy.py` and `docs/validation/fitting_accuracy.md`:
  Monte Carlo bias and precision of the FWHM measurement.
- Tracking (M3):
  - results database (`sqlite3`), append-only by trigger, with an audit
    log of every record, exclusion, inclusion, and event (TRK-01, NFR-07);
  - results filed by instrument, objective, channel, and modality (TRK-02);
  - baselines from the first N sessions, a date range, or targets, with
    provisional limits while collecting (TRK-04);
  - Westgard rules 1_2s, 1_3s, 2_2s, R_4s, 4_1s, 10_x, configurable per
    metric in a profile's `[tracking]` table (TRK-05);
  - events that annotate charts and can start a new baseline (TRK-06);
  - exclusion and re-inclusion of sessions with a reason (TRK-07);
  - Levey-Jennings charts (PNG, SVG, PDF) with limits, events, exclusions,
    rule violations, and spec limits (TRK-03, TRK-08);
  - drift per month over recent sessions (TRK-09);
  - CSV export and database backup (TRK-10);
  - `psfwidget analyze --db` and `psfwidget track list|status|chart|event|
    exclude|include|export|backup|audit`;
  - `tools/demo_tracking.py`, which builds a demonstration database from
    simulated weekly sessions.
- Reports (M4, WP5):
  - session reports with an overall status and its reasons, acquisition
    settings, metric summary against theory, Westgard and spec checks, bead
    overview, XY/XZ/YZ views, profile fits, bead table, and provenance
    (REP-01, REP-06, REP-07);
  - trend reports with latest status, rule violations, events, and
    Levey-Jennings charts over a period (REP-02);
  - self-contained HTML and PDF (letter or A4) from one report model
    (REP-03); XLSX export (REP-04);
  - output folder and file name templates that never overwrite (REP-05);
  - facility name, logo, and footer on every report (REP-08);
  - `psfwidget analyze --report html,pdf --xlsx` and `psfwidget report trend`.
- Automation (M4, WP6):
  - TOML configuration with validation and clear messages, and
    `psfwidget check-config` (AUT-05); example in `examples/automation/`;
  - watch-folder ingestion with a settle time, deduplication by file hash,
    and per-file error isolation (AUT-02, NFR-06);
  - plain-word schedules for ingestion and trend reports, run by
    `psfwidget run` (cron, Task Scheduler) or `psfwidget watch` (AUT-03);
  - a log and a JSON summary of every run, and a lock against overlapping
    runs (AUT-04);
  - `STATUS.json` after every run and `ALERT.txt` while something needs
    attention (AUT-06).
- napari GUI (M5, WP7), installed with `pip install "psfwidget[napari]"`:
  - analysis widget: open a file and series, edit metadata, analyse in a
    background thread, review accepted and rejected beads in 2D or 3D,
    record, and write reports (UI-01, UI-04);
  - manual bead review: include or exclude beads with a reason and
    reviewer, with the summary and spec checks recomputed (DET-07;
    `psfwidget.review`);
  - tracking widget: interactive Levey-Jennings charts with hover details,
    exclusion and re-inclusion, and events (UI-02);
  - profile editor with validation and TOML saving (UI-03;
    `psfwidget.profiles.write`);
  - npe2 plugin manifest and a synthetic bead sample (T7.4);
  - a GUI job in CI (headless napari under a virtual display).

### Changed
- Reports use a block-based model with `reportlab` for PDF instead of
  Jinja2 templates and `weasyprint`, and scheduling uses PSFWidget's own
  state file instead of APScheduler.
- The averaged-PSF OME-TIFF export (REP-04) moves to M5 with the averaged
  PSF (MET-14).
- NFR-01 now applies its 3%/5% limits to the median of a 10-bead field, and
  adds a per-bead bias limit of 1%.
- `scipy` is a core dependency; `matplotlib` is in the optional `report` extra.
- Storage uses the built-in `sqlite3` instead of SQLAlchemy and Alembic.
- Minimum Python is 3.12 (required by the BSD reader libraries); CI runs
  3.12-3.14.
- Theoretical PSF models will be implemented in PSFWidget. `psfmodels` is
  GPL-3.
- Scope: spinning-disk confocal added (THE-01). Resolution-enhanced modes
  (NSPARC SR, Live-SR) keep a theoretical comparison (new THE-08, THE-09).
- TRK-02: acquisition dates come from file metadata, never from file names.
- Planned file readers are now `nd2`, `liffile`, `czifile`, and `tifffile`.
  `bioio-czi` and `readlif` are GPL-3 and conflict with the MIT licence.
