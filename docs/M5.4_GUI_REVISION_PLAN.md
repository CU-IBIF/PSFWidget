## 4. Defect DEF-01: error on load

**Symptom.** Opening a file raises `AttributeError: 'NoneType' object has no
attribute 'height'` from napari's layer list (`LayerDelegate._paint_loading`),
through a chain of `index()`/`flags()` calls.

**Diagnosis.**
- **napari side:** when napari draws a layer that is still loading, it asks
  the layer list for the row height. It does not check whether the answer is
  `None`, which it is when that row has just been removed. This is a bug in
  napari; napari 0.10.0 still has it.
- **PSFWidget side:** our code removes and adds several layers in one burst:
  - every time a file is opened, all old layers are removed and all new
    layers added (`_opened`);
  - after every review, the point layers are removed and re-added
    (`_show_points`).
- **Why it fails:** the layer list is redrawn while those rows change and the
  new layers are still loading. Large stacks and napari's asynchronous
  slicing make this more likely.

**Fix.**
1. Reproduce it first, on Windows and in the Linux CI under a virtual
   display: open twice in a row, open while a large stack is still loading,
   and review repeatedly, each with asynchronous slicing on and off.
2. Update layers in place instead of removing and re-adding them:
   - image layers get new data, scale, and contrast;
   - point layers get new coordinates, colours, and features.
   Only add or remove layers when the number of channels changes, and do it
   once, after the worker has finished.
3. If it still occurs, defer layer changes to the next turn of the Qt event
   loop (`QTimer.singleShot(0, …)`).
4. Report the missing check to napari, with your agreement, and record the
   napari versions we have tested in the install guide.

**Verification.** The regression tests in §6.2 (T-DEF-01), on Linux CI and on
a Windows CI job, plus GUI test script step G4 on the facility PC.

**Outcome (2026-11-20).** D1–D3 done; 17 new tests in
`tests/test_gui_reader.py`.
- **DEF-01 was not reproduced here.** Opening files repeatedly and reviewing
  repeatedly, in a shown viewer with asynchronous rendering on and off
  (napari 0.10.0, PySide6 6.12, Linux), raised no error. The traceback shows
  napari reading "is this layer loaded?" and "row size" as `None`, which
  happens only for a row that has gone while the list is drawn.
- **So the fix is defensive, in two parts:**
  - the widget updates its layers in place, so it no longer creates the
    condition;
  - a guard makes napari's layer list skip a vanished row instead of raising.
    A test feeds the guard exactly that condition.
  Confirmation needs the facility re-test (G4) and `napari --info` from the PC.
- **Found and fixed:** a file with no recorded voxel size raised an error when
  shown (found by the drop test on `BF007.nd2`). It is now shown at 1 µm per
  voxel along the unknown axis.
- **D4 partly done.** The Windows GUI job runs in CI, but it does not block
  yet. On the Windows CI machines, 14 GUI tests pass and the 9 that draw an
  image fail at napari's first OpenGL call (`GL_MAX_TEXTURE_SIZE`, "invalid
  operation"). The CI machines have only software OpenGL, and using napari's
  own CI set-up for it did not help. This is a CI environment problem, not a
  PSFWidget one: the facility PCs have graphics drivers. Until it is solved,
  the Windows GUI checks rely on the manual GUI test script on the facility PC
  (A4, A5, G4).
- **Changed from the plan:** the series dialog shows data type instead of
  voxel size. Reading every series' metadata to get it would slow large LIF
  projects.

## 6. Verification and validation strategy

Verification shows the software meets the requirements; validation shows it
meets the user needs on the facility's PCs. Every new or changed requirement
has at least one automated test linked with `pytest.mark.req`, so it appears
in `docs/traceability.csv` and the requirement coverage report.

### 6.1 Levels

| Level | What | Where |
|---|---|---|
| Unit | Logic without Qt, in `napari/session.py`: series listing, bead-table rows, decisions needing an explanation, reviewer identity, report contents | CI, all 3 OS × Python 3.12–3.14 |

## 7. Risks

| Risk | Mitigation |
|---|---|
| The crash also has a cause in napari that changing our layers does not avoid | Reproduce before fixing (§4 step 1); fallback of deferred layer changes; report upstream; pin tested napari versions |
| Other installed plugins also claim `.tif` or `.nd2` (napari's built-in TIFF reader, napari-nd2), so napari asks which reader to use | Document "Open with PSFWidget" and the reader-preference setting; test with napari's built-ins installed |
| Large files dropped onto napari load the whole stack into memory | Same loading path as *Browse*, which is already tested on the facility files; a size warning above 2 GB |
| The login name can be faked through environment variables on Windows | Read the identity from the Windows account API rather than environment variables; record the host as now |
| Removing GUI approval slows the review workflow | Command-line approval stays; the GUI section returns in a later milestone without code changes |
| A shorter report is less complete for GLP | Full bead list in CSV/XLSX, reviewer changes in the report and audit trail |

## 8. Questions for the reviewer

Each has a proposed answer that this plan assumes; please confirm or change.

1. **Including rejected beads.** Can a reviewer include an automatically
   rejected bead by ticking its box (with an explanation)? *Proposed: yes,
   as today.*
2. **Table scope.** Does the bead table show the selected channel only (with
   the existing channel selector)? *Proposed: yes.*
3. **Report.** Should the report list beads changed by a reviewer, with the
   explanation? *Proposed: yes, for traceability; usually only a few rows.*
4. **Two-way link.** Should clicking a bead in the image also select its row?
   *Proposed: yes, if it fits in M5.4b; otherwise next milestone.*
5. **Missing values.** Required values that are missing have a pale red fill,
   which has the same contrast problem. Should they get a red outline?
   *Proposed: yes.*
6. **Series.** Is one series at a time enough in the GUI? *Proposed: yes;
   batch analysis stays on the command line.*
7. **For reproducing DEF-01:** please send the output of `napari --info` from
   the PC that showed the error, and whether asynchronous rendering is on
   (*Preferences → Experimental*).
8. **Approval return.** When should GUI approval come back: with M6
   validation, or after it?
